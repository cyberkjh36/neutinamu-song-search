# 0.11.7 · 현재 재생곡 표시와 연결 유지·복구

예약곡 목록 위에 **현재 재생 중인 곡의 제목·가수·곡번호**를 별도로 표시합니다. 예약 순번과 개수에는 포함하지 않으며 같은 곡이 다시 예약되어 있어도 삭제하거나 합치지 않습니다.

- 인증된 P2의 재생 알림(4300)을 세션 전체에서 처리합니다. 다른 리모컨에서 바뀐 곡도 알림이 오면 갱신합니다. 검색 결과 선택이나 시작 요청 접수만으로 현재 곡을 추정하지 않습니다.
- 정지 응답을 받으면 현재 곡 표시를 비우며, 연결 해제·방 변경·잘못된 정보에서도 이전 곡을 남기지 않습니다. 곡번호가 데이터에 없으면 번호와 ‘제목 정보 없음’을 표시합니다.
- 연결 당시 이미 재생 중인 곡은 P2의 새 재생 알림을 받을 때까지 확인 대기로 표시합니다. 확인되지 않은 상태 조회 명령을 만들어 보내지 않습니다. 곡 종료 알림이 없는 기기에서 종료 시점까지 추정하지 않습니다.

연결이 자주 끊긴다는 추가 보고에 따라 다음을 보완했습니다. 최신 끊김 진단이 없어 현장의 단일 원인을 확정하지는 않습니다.

- 연결 준비·유지 중에만 Android `connectedDevice` 전경 서비스와 CPU/Wi-Fi 잠금으로 화면 꺼짐·다른 앱 사용 중 통신을 보호합니다. 해제·실패·앱 종료 시 정리하며, 서비스를 자동 재시작하거나 화면을 계속 켜 두지 않습니다.
- 연결 유지 응답의 허용 공백을 30초에서 60초로 조정했습니다. 초기 인증·곡 명령 응답의 10초 제한은 유지합니다.
- 이미 인증된 같은 방에서 발생한 통신 오류만 1.5/4/9초 간격으로 최대 3회 복구합니다. 매번 같은 방을 다시 찾고 실제 네트워크와 반주기 일련번호를 재확인합니다. 앱이 화면에 없을 때의 재검색은 돌아올 때 진행합니다.
- 수동 연결 해제·복구 취소·인증 거절·기기 불일치·권한 문제에는 재접속하지 않습니다. 짧게 연결됐다 끊기는 현상은 같은 시도 횟수 제한을 공유하고, 1분 이상 안정된 연결 후에만 횟수를 초기화합니다.
- 복구는 연결만 수행하며 곡 시작·정지·예약·다음곡 명령을 재전송하지 않습니다. 기존 방 QR, 손님 등록 형식, 검색과 예약 동작을 유지합니다.

검증: 재생 알림/정지/정보 없음/연결 해제의 모의 TCP 시험, 복구 횟수·같은 방 제한·수동 취소·백그라운드 복귀 시험, Android 서비스 잠금/알림/정리 시험, Chromium의 현재 곡·예약 목록 분리/제목 표시/작은 화면 시험을 포함합니다. 실제 휴대폰 절전 동작과 매장 P2의 알림·재접속은 현장 검증이 필요합니다.

Android 공식 참고: https://developer.android.com/develop/background-work/services/fgs/service-types · https://developer.android.com/develop/background-work/background-tasks/awake/wakelock

# 0.11.6 · 정지, 다음곡 실행, 예약곡 선택 실행

사용자가 0.11.5의 방 연결 정상 동작을 확인했습니다. 이번 변경은 연결·인증·방 대응표를 유지하고 곡 제어와 표시를 수정합니다.

- 휴대폰 화면의 일시정지를 제거하고 **정지 / 다음곡 실행**을 표시합니다. 검색 결과를 지워도 연결 중에는 사용할 수 있습니다.
- **정지**는 기존의 현재 곡 취소 명령(4100/12)을 한 번 전송합니다.
- **다음곡 실행**은 최신 예약 목록(4200)을 확인한 뒤 현재 곡 정지 응답을 기다리고, 곡번호 없는 시작(4100/11)을 한 번 보냅니다. 예약곡이 없으면 현재 곡을 중단하지 않습니다.
- **예약 목록에서 곡을 누르면** 최신 목록의 같은 위치·곡번호를 다시 확인하고, 정지 응답 후 해당 곡번호 시작(4000/1200)을 요청합니다. 순서가 바뀌면 새 목록에서 다시 선택하도록 안내합니다.
- 시작 명령의 접수와 실제 곡 재생 상태(4300)를 구분합니다. 선택 곡의 재생 상태를 받으면 P2 예약 목록을 다시 읽습니다. 휴대폰이 임의로 예약을 삭제하거나 성공한 것처럼 목록을 수정하지 않습니다.
- 연속 탭, 잘못된 목록, 정지 거절·시간 초과·연결 종료에서는 후속 시작이나 자동 재전송을 하지 않습니다. 제목/가수/초성/음성 검색, 예약, 기존 방 QR 및 설치 서명은 유지합니다.

검증 범위: 모의 TCP 서버에서 각 단계의 패킷·응답·오류·시간 초과를 검사하고 Android 브리지·화면, 실제 Chromium의 터치·키보드·작은 화면 동작을 검사합니다. 새 제어 기능의 실제 P2 소리·화면 반영은 현장 확인이 필요합니다. 아래는 이전 버전의 변경 기록입니다.

# 0.11.5 · QR 손님 연결과 직원 연결 정보 분리

0.11.4 현장 로그에서 무선 연결과 TCP 접속 뒤 초기 요청에 오류 3003이 반환되었습니다. 같은 휴대폰·같은 방에서 공식 앱은 정상이라는 사용자 확인을 받았습니다. 오류 3003의 세부 원인 및 최초 연결 끊김 원인은 아직 확정하지 않았습니다.

- QR/방 선택 연결은 제공받은 마이 티제이의 손님용 식별값 2를 사용합니다. 이전 자동 생성 경로는 업주용 캡처의 값 4를 사용했습니다.
- 저장 기록이 같은 방이면 이미 알려진 연결 암호만 사용하고, 직원의 계정 필드나 업주용 모드를 QR 연결에 섞지 않습니다. 다른 방의 암호는 사용하지 않으며 암호를 추측하거나 거절 후 다른 모드로 자동 재시도하지 않습니다.
- 직원용 ‘기존 직접 연결 확인’ 경로와 암호화된 저장 기록은 유지합니다. 실제 휴대폰 주소와 반주기 전체 일련번호 검증도 유지합니다.
- 진단에 접속 시도/승인 횟수와 최초/최근 연결 실패 코드를 별도로 남겨, 무선 상태 이벤트가 반복되어도 실패 근거가 사라지지 않게 했습니다. 개인정보·주소·인증값은 기록하지 않습니다.
- 모의 TCP 서버의 연결→재생→연결 종료→새 연결, 연결 유지 응답, 이전 곡 명령 재전송 방지를 검증합니다. 실제 P2의 초기 승인·재접속은 현장 검증이 필요합니다.

# 0.11.4 · 무선 검색 이름과 전체 일련번호 구분

현장 진단은 주변 P2 후보가 있으나 등록 방이 0개임을 보였고, 이전 기기 목록 사진과 배포 APK를 비교해 무선 이름에서 생략된 P020 접두어가 원인임을 확인했습니다.

- 검색 이름의 알려진 두 형식만 대조합니다. 전체 일련번호가 담긴 매장 대응표는 그대로 두고 검색에만 짧은 이름을 적용합니다.
- QR 자동 선택과 수동 방 선택, 진단의 등록 방 집계에 동일한 기준을 사용합니다. 일련번호와 끝 식별값이 다르면 일치시키지 않습니다.
- 동일 이름의 여러 주소 또는 같은 무선 이름에 여러 방이 대응하면 연결하지 않습니다. 실제 Wi-Fi 주소와 반주기 응답의 전체 일련번호 검증은 유지합니다.
- 기존 앱 위에 업데이트하며 앱 이름, 방별 QR, 저장 설정을 유지합니다. 실제 무선 연결과 P2 응답 확인은 현장 재시험이 필요합니다.

# 0.11.3 · 앱 이름 변경

안드로이드 설치·홈 화면의 앱 이름과 앱 내부의 메인 제목, 문서 제목, 진단 보고서 제목을 **느티나무노래방 전용 리모컨**으로 통일했습니다. 패키지 이름과 서명, QR, 방 대응표 및 연결·검색·곡 제어 기능은 0.11.2와 동일합니다. 기존 앱 위에 업데이트합니다.

# 0.11.2 · 검색 결과 재확인과 연결 설정 안내

최신 현장 사진에서도 W21 검색 시간 초과가 보고되었습니다. QR 방 인식 뒤 무선 검색 단계의 실패이며 사진만으로 휴대폰 설정, 무선 발견 실패, 기기명 불일치 중 원인을 확정하지 않습니다.

- 검색 중 1초 간격으로 Android의 현재 기기 목록을 재확인합니다. 알림 없이 늦게 도착하는 결과도 처리하고, 기존 20초 제한 안에서만 조회합니다. 선택·취소·시간 초과·화면 종료 시 조회를 중단하며 이전 검색이나 오래된 목록의 응답은 무시합니다.
- Wi-Fi 꺼짐(W30), Android 12 이하의 위치 기능 꺼짐(W31)을 검색 전에 확인하고 해당 설정을 여는 버튼을 제공합니다. 설정에서 돌아와 준비되면 선택한 방 검색을 이어갑니다. 위치 좌표는 요청하거나 수집하지 않습니다.
- 진단에 검색 시작 승인/거절 사유와 전체 발견 수·등록 방 수·미등록 P2 후보 수·이름 누락 수를 남깁니다. 기기명·MAC·주소는 기록하지 않으며 같은 결과는 반복 기록하지 않습니다.
- 기존 방 대응표, QR, 정확한 같은 방 제한, 서명, 검색·제어 기능은 유지합니다. 무선 기기 검색 보완과 진단 개선이며 실제 P2 무선 연결 또는 인증 성공을 보증하지 않습니다. 현장 재검증이 필요합니다.

# 0.11.1 · 등록된 방 검색과 방번호 표시

새로 제공된 매장 대응표를 0.11.0 배포 APK와 대조했으며 등록된 7개 방은 모두 일치했습니다. 방번호는 기기 ID의 끝 숫자로 추정하지 않고 매장 대응표를 사용합니다.

- Wi-Fi Direct 검색 결과에서 등록된 기기 이름이 정확히 일치하면 WPS 기기 종류가 누락되거나 달라도 해당 방을 인식합니다. 기존 종류 필터 때문에 알려진 방이 숨겨질 수 있던 경로를 수정했습니다.
- 방 선택 목록에는 검색된 등록 방만 숫자 순서로 표시합니다. 기기 ID와 미등록 장치는 손님 목록에 노출하지 않습니다. 실제 접속 주소와 반주기 식별 확인은 유지합니다.
- QR의 같은 방 제한과 중복 기기 차단, 통합 화면과 검색·실행·예약·일시정지·예약 목록을 유지합니다.

이 변경만으로 매장에서 보고된 W21의 원인을 확정하거나 실제 무선 연결 성공을 보증하지 않습니다. 휴대폰과 반주기에서 후속 검증이 필요합니다. 방별 대응표와 서명 키는 공개 저장소에 포함하지 않습니다.

# 0.11.0 · QR 연결과 노래 검색을 한 화면으로 통합

방 QR을 스캔하면 앱의 같은 화면 상단에서 해당 방의 연결 진행 상태와 결과를 확인합니다. 아래에서 음성, 제목, 가수, 초성, 곡번호로 검색하고 결과 아래의 **실행 / 예약 / 일시정지 / 예약곡 목록**을 이용합니다. 곡 취소와 새 검색도 유지합니다. 검색 결과가 많으면 30곡씩 더 볼 수 있습니다.

- 별도의 중복 검색 화면을 제거했습니다. 상단 `P2 연결`은 직접 연결을 시작하며 설정 화면으로 이동하지 않습니다. 이미 연결된 경우 `연결 해제`로 표시합니다.
- 연결 기록, 진단 공유, Wi-Fi 설정, CSV 관리 등은 더보기에 유지했습니다. 직원용 연결 도움말은 검색 화면을 그대로 둔 채 대화상자로 엽니다.
- 일시정지 버튼은 P2 제어 키 25를 한 번 전송합니다. 같은 버튼으로 계속 재생을 요청하며, 명령 처리 중 중복 입력과 자동 재전송을 막습니다. 응답 확인과 실제 정지 상태를 구분합니다.
- QR의 방 제한, 정확한 무선 인터페이스 선택, N10 주소 준비 대기와 같은 방 재검색, 곡 시작·취소, 실제 예약 목록 조회, 저장된 연결 정보와 앱 서명을 유지합니다.

실제 P2 기기에서 새 일시정지 기능의 동작은 추가 확인이 필요합니다. 테스트 응답만으로 현장 동작을 보증하지 않습니다. 기존 앱 위에 업데이트하며 방 QR은 그대로 사용합니다.

이 브랜치는 안드로이드 직접 연결 앱용입니다. 웹앱 전체를 public main으로 병합하지 않습니다. 개인 방 설정과 서명 키, PCAP 및 공식 앱 원본은 저장소에 넣지 않습니다.

## 이전 연결 수정 내역

# 0.10.1 · P2 연결 버튼과 N10 재시도 수정

사진의 N10은 앱이 열렸지만 반주기에 연결할 직접 Wi-Fi 경로를 찾지 못했다는 의미입니다. 저장된 인증 정보만으로 무선 연결이 있다고 가정하던 연결 버튼 경로를 수정했습니다.

- 방 QR이 있으면 연결 버튼을 다시 눌러도 같은 방만 재검색합니다. 이전 그룹의 주소·인터페이스를 재사용하지 않습니다.
- QR 방이 없는 경우 저장 프로필이 있어도 주변 반주기 검색과 방 선택부터 진행합니다. 직원이 ‘기존 직접 연결 확인’으로 확인한 경로는 다시 상태를 확인한 뒤 유지합니다.
- 선택한 방번호와 찾는 중·연결 준비 중·연결 전·연결됨을 표시합니다. 검색 중 연속 클릭은 검색을 반복하거나 제한 시간을 늘리지 않습니다.

# P2 직접연결 0.9.0: 방 QR에서 새 휴대폰 연결 시작

방 QR(기존 HTTPS 주소 또는 `neutinamu-p2://connect?room=N`)로 앱이 열리면, 연결 기록 파일 없이 해당 방의 실제 Wi-Fi Direct 기기를 찾아 연결하고 반주기 응답을 확인합니다. 권한 허용 후에는 같은 연결 절차를 이어갑니다. 음성·초성 검색, 명시적인 곡 시작·취소, 제작자 표시는 유지합니다.

- PCAP을 미리 등록하지 않은 폰에서는 사용자가 제공한 P2 기록에서 확인한 비밀번호 0 / 프로토콜 표식 4 구성을 사용합니다. 전화번호는 공식 클라이언트의 미제공 값 형식으로 채우며 개인 전화번호나 과거 MAC을 배포하지 않습니다. 비밀번호가 다른 반주기에 다른 값을 추측하거나 반복 시도하지 않습니다.
- 저장된 기록이 있더라도 **현재 선택한 방의 기기 일련번호가 같은 경우에만** 재사용합니다. 다른 방 기록이 새 방 연결을 가로막지 않습니다.
- 실제 발견한 Wi-Fi Direct 기기 주소와 연결 그룹 소유자, 반주기 응답의 20바이트 식별 필드에 담긴 일련번호를 순서대로 확인합니다. 다른 기기·중복 이름·일련번호 불일치이면 연결 완료로 표시하거나 곡을 보내지 않습니다.
- QR로 연결이 완료되면 노래검색 화면을 보여 줍니다. QR을 읽기만 해서는 노래가 실행되지 않습니다. 다른 방 연결 중에 QR을 찍어도 기존 연결을 임의로 끊지 않습니다.
- 처음에는 Android의 근처 기기 또는 위치 권한/위치 기능, Wi-Fi Direct 연결 승인이 필요할 수 있습니다. 앱은 이를 자동 승인하지 않습니다.
- **실기 미검증:** 새 손님 폰의 최초 무선 연결, 익명 등록 허용 여부, 7개 방 전체의 동일 연결 설정은 매장에서 확인해야 합니다. 현재 Wi-Fi Direct 주소를 Android가 제공하지 않으면 A03으로 중단하며 임의 주소를 사용하지 않습니다.
- HTTPS QR의 앱 자동 실행에는 `https://cyberkjh36.github.io/.well-known/assetlinks.json`의 연결 확인 파일 배포가 필요합니다. 앱의 manifest만 추가해도 검증이 완료되는 것은 아닙니다. 브라우저로 열리면 기존 페이지의 연결 버튼을 사용합니다. Chrome은 사용자 동작 없는 타이머로 앱을 여는 방식을 보장하지 않습니다.

이하 항목은 이전 버전의 변경 기록입니다. 초기 PCAP 필수 안내는 0.9.0의 등록된 방 QR 연결 경로에는 적용하지 않습니다.

1. **P2 직접연결 0.6**을 엽니다. 저장된 연결 정보가 있으면 자동으로 불러옵니다.
2. 처음 사용하는 휴대폰에서는 **P2 연결**을 눌러 이전 PCAP 파일을 선택합니다. 이미 저장했다면 파일 선택을 생략합니다.
3. **주변 P2 찾기**에서 반주기를 선택합니다. 이미 직접 Wi-Fi에 연결되어 있다면 상단 **P2 연결**을 사용할 수 있습니다.
4. 상단에 **P2 연결됨**이 표시되면 제목·가수·곡번호를 입력하고 **검색**을 누릅니다.
5. 결과에서 원하는 곡을 선택하고 제목과 번호를 확인한 뒤 **▶ 곡 시작**을 누릅니다.
6. 노래를 멈추려면 **■ 곡 취소**, 다른 노래를 찾으려면 **새 검색**을 누릅니다.

노트9/안드로이드10에서는 Wi-Fi와 위치 기능, 위치 권한이 켜져 있어야 주변 기기를 검색할 수 있습니다. 위치를 수집하지 않습니다. P2 설정에 따라 NFC 연결 준비가 필요할 수 있으며, NFC 없이 처음부터 연결되는지는 별도 실기 확인이 필요합니다.

기존 직접 연결을 확인하거나 TJ매니저와의 연결 충돌을 해결할 때는 **연결 설정 · 도움말 → 기존 직접 연결 확인 → 필요 시 TJ매니저 설정 → P2 연결**을 사용하세요.

연결 정보는 휴대폰 안에 암호화해 보관하며 자동으로 노래를 실행하거나 반주기에 접속하지 않습니다. 앱 삭제·데이터 초기화, 휴대폰 변경, 반주기 연결 정보 변경 시에는 파일을 다시 선택해야 합니다. **저장된 연결 정보 지우기**는 원본 PCAP과 반주기의 노래를 삭제하지 않습니다.

## 진단과 확인 범위

실패하면 **연결 설정 · 도움말 → 진단 결과 복사**를 누르고 현재 ChatGPT 대화에 붙여넣어 주세요. 공유 버튼도 사용할 수 있습니다. 개인정보, MAC, 비밀번호, 원본 패킷은 진단에 넣지 않습니다.

| 코드 | 의미 |
| --- | --- |
| W21 / W25 | 주변 검색 또는 무선 연결 실패·시간 초과 |
| W24 | 선택한 반주기와 현재 직접 연결이 다름 |
| A03 | 휴대폰의 현재 직접 Wi-Fi 주소를 읽지 못함 |
| A01 / 3003 | 초기 응답이 성공 형식이 아님. 3003의 정확한 의미는 미확인 |
| A02 | 초기 연결 응답 시간 초과 |
| I01 | 저장된 반주기 식별정보와 불일치 |
| READY | 통신 연결 및 반주기 식별정보 확인 완료 |
| P10 | 시작 요청에 대한 응답. 실제 소리 확인과는 별도 |

사용자 확인은 0.4에서의 10909번 시작·취소입니다. 공유된 진단 일부에서 취소 응답 `4100 / 12`, READY 복귀, 약 1분 동안 연결 확인 신호가 이어진 사실을 확인했습니다. 해당 부분에 시작 요청 자체는 포함되어 있지 않습니다. NFC 없이 새 연결하기, 여러 휴대폰 동시 접속, 장시간 안정성은 별도 실기 확인이 필요합니다. iPhone 직접 제어는 아직 지원하지 않습니다.

## 개발 검증과 저장 방식

`gradle -p p2-direct :core:test :app:testDebugUnitTest :app:assembleDebug :app:lintDebug`

기존 통신·검색·Wi-Fi 연결 테스트에 더해, 암호화 저장·재시작 복원·삭제·손상 검출·잘못된 키·저장 실패 시 기존 정보 보존·반복 신호 후 시작/취소 기록 보존을 검사합니다. 0.6에서는 30곡 이후 페이지 이동·정확한 곡번호 우선·제목/가수 조합·새 검색의 늦은 결과 무시·번호/제목 동기화·접기/펼치기·연결 상태 표시와 작은 휴대폰 화면도 검사합니다. 에뮬레이션 검증은 실제 반주기 및 휴대폰 Keystore 검증을 대체하지 않습니다.

프로필은 Android Keystore의 AES-256-GCM 키로 암호화하고 앱 전용 백업 제외 디렉터리에 원자적으로 저장합니다. 공개 저장소에는 공식 앱 APK/복원 코드와 개인 통신 기록을 포함하지 않습니다. 참고: [Android KeyGenParameterSpec](https://developer.android.com/reference/android/security/keystore/KeyGenParameterSpec).

0.5부터 배포 서명키를 별도로 보관해 이후 같은 앱 ID(`kr.neutinamu.p2.direct`)로 업데이트할 수 있도록 구성했습니다. CI의 임시 디버그 APK는 검증용이며, 사용자에게 제공하는 APK는 디버그 기능을 끈 릴리스 빌드를 별도 배포 키로 서명합니다. 개인 키와 연결 정보는 저장소와 CI 산출물에 포함하지 않습니다.
