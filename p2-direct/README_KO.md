# 느티나무 P2 직접연결 시험판 0.4

휴대폰에서 곡을 검색하고 P2에 시작·취소 명령을 보내기 위한 **안드로이드 시험 앱**입니다. 실제 P2 연결과 재생 성공은 아직 확인되지 않았습니다. 기존 WorldKaraoke와 GitHub Pages는 변경하지 않습니다.

## 이번 수정

- 주변 P2를 찾아 선택하고 Wi-Fi Direct 연결을 요청하는 기능을 추가했습니다.
- 이전 기록의 휴대폰 주소 대신 현재 직접 연결의 주소를 사용합니다.
- 연결 성공 응답의 사용자 식별값을 `0`만 허용하던 오류를 수정했습니다.
- 연결별 설정값을 이후 명령에도 유지하며, 오류 응답을 성공으로 취급하지 않습니다.
- 진단 결과에 연결 종료 원인 코드를 남깁니다.

## 사용 순서

1. `P2 직접연결 0.4`를 엽니다. 0.3과 아이콘 이름이 다릅니다.
2. **내 PCAP 연결 기록 선택**에서 전에 추출한 P2 통신 기록을 선택합니다. 새로 녹화하라는 뜻이 아닙니다. 연결정보는 메모리에만 유지하고 서버에 보내지 않습니다.
3. 휴대폰 Wi-Fi를 켜고 **② 주변 P2 찾기**를 누릅니다. 노트9/안드로이드10에서는 위치 기능과 위치 권한도 켜야 기기 검색이 가능합니다. 위치를 수집하지 않습니다.
4. 목록에서 해당 반주기를 선택합니다. P2나 휴대폰에 연결 승인 화면이 나오면 확인합니다.
5. **[READY] P2 연결 응답 확인**이 나온 뒤 곡번호 `10909` 또는 노래 제목으로 검색하고 **선택한 곡 시작**을 누릅니다.
6. 반주기 화면과 소리로 확인하고, **현재 곡 취소**도 시험합니다.

직접 검색에서 P2가 나오지 않으면 반주기가 연결 대기 상태인지 확인해야 합니다. P2 설정에 따라 먼저 NFC로 연결을 준비해야 할 수 있으며, NFC 생략을 보장하는 완성판은 아닙니다. TJ매니저가 이미 연결 중이면 충돌 가능성도 있습니다. 기존 연결을 이용하려면 ① 기존 직접 연결 확인 → 필요 시 TJ매니저 설정 → ③ P2 연결 시험을 이용할 수 있습니다.

## 결과 확인

- `W21`: 주변 반주기 검색 실패
- `W24`: 선택한 반주기와 실제 직접 연결이 다름
- `W25`: 무선 연결 요청 실패 또는 시간 초과
- `A03`: 현재 휴대폰 인터페이스 주소를 읽지 못함. 이전 주소로 대신 접속하지 않음
- `A01` / `3003`: 초기 응답이 연결 성공 형식이 아님. 정확한 오류 의미는 미확인
- `A02`: TCP 접속 후 초기 연결 응답 시간 초과
- `I01`: 저장된 반주기 식별정보와 불일치
- `READY`: 프로토콜 연결 및 반주기 식별정보 확인 완료
- `P10`: 시작 요청에 응답이 옴. 실제 재생 확인과 다름

실패하면 **진단 결과 공유** 또는 **진단 결과 복사**로 결과를 보내 주세요. 원본 통신 기록, 휴대폰 번호, MAC, 비밀번호는 진단 메시지에 넣지 않습니다.

## 한계 및 개발 검증

초기 연결 설정은 기존 PCAP에서 가져옵니다. 반주기 비밀번호가 바뀌면 이전 기록이 맞지 않을 수 있습니다. 최신 안드로이드에서 인터페이스 주소 조회가 제한되면 A03으로 중단하며 주소를 임의로 만들지 않습니다. iPhone 직접 제어는 미구현입니다.

`gradle -p p2-direct :core:test :app:testDebugUnitTest :app:assembleDebug :app:lintDebug`

테스트는 프레임 분할, 현재 주소 적용, 연결 설정 유지, 데이터/오류 구분, 사용자 식별값, 동일 반주기 확인, 중복 명령 방지, Wi-Fi 검색·선택·연결 상태, 시간 초과 및 늦은 콜백을 검사합니다. 물리 반주기 동작은 별도 확인이 필요합니다. 공개 저장소에는 공식 앱 APK/복원 코드와 개인 통신 기록을 포함하지 않습니다.
