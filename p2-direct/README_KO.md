# 느티나무 P2 직접연결 시험판 0.5

휴대폰에서 곡을 검색하고 P2에 시작·취소 명령을 보내는 안드로이드 앱입니다. **2026년 11월 6일(한국 시간), 사용자가 0.4에서 실제 P2의 10909번 곡 시작과 취소가 정상 작동한다고 확인했습니다.** 0.5는 그 통신 방식을 유지하면서 연결 정보 저장과 진단 기록을 개선합니다. 기존 WorldKaraoke와 GitHub Pages는 변경하지 않습니다.

## 달라진 점

- PCAP에서 필요한 연결 정보를 가져온 뒤 휴대폰 안에 암호화해 저장합니다. 앱을 다시 열면 자동으로 불러옵니다.
- 자동으로 노래를 실행하거나 반주기에 접속하지 않습니다. 연결할 P2를 선택하고, 원하는 곡의 시작 버튼을 눌러 주세요.
- 저장한 연결 정보는 ‘저장된 연결 정보 지우기’로 삭제할 수 있습니다. 원본 PCAP과 반주기의 노래는 그대로 유지됩니다.
- 진단 결과에서 반복되는 연결 확인 신호는 횟수와 마지막 시각으로 요약합니다. 대기 중에도 실제 시작·취소 기록이 밀려나지 않습니다. 주요 이벤트는 최근 48개까지 유지합니다.
- 잘못된 저장 정보나 저장 실패를 안내하며, 인증값을 진단 메시지에 넣지 않습니다.

## 사용 순서

1. 새 앱 **P2 직접연결 0.5**를 엽니다. 이전 0.4와 별도로 설치됩니다. 한 번에 한 앱만 P2에 연결하세요.
2. 처음에는 **내 PCAP 연결 기록 선택**에서 전에 보내 주신 파일을 선택합니다. 새로 녹화할 필요는 없습니다. ‘연결 정보를 암호화해 저장했습니다’ 문구를 확인하세요.
3. 휴대폰 Wi-Fi를 켜고 **② 주변 P2 찾기**를 누릅니다. 노트9/안드로이드10에서는 위치 기능과 위치 권한도 켜야 기기 검색이 가능합니다. 위치를 수집하지 않습니다.
4. 목록에서 해당 반주기를 선택합니다. P2나 휴대폰에 연결 승인 화면이 나오면 확인합니다.
5. **[READY] P2 연결 응답 확인**이 나온 뒤 곡번호 `10909` 또는 노래 제목으로 검색하고 **선택한 곡 시작**을 누릅니다.
6. 노래를 끝내려면 **현재 곡 취소**를 누릅니다.

다음 실행부터 2번 파일 선택은 생략할 수 있습니다. 앱 삭제·데이터 초기화, 휴대폰 변경, 반주기 연결 정보 변경 시에는 다시 선택해야 합니다. 파일을 저장하는 데 실패했다면 화면 안내에 따라 다음 실행 때 다시 선택하세요.

주변 검색에서 P2가 나오지 않으면 반주기가 연결 대기 상태인지 확인해야 합니다. P2 설정에 따라 먼저 NFC로 연결을 준비해야 할 수 있습니다. 기존 연결을 이용하려면 **① 기존 직접 연결 확인 → 필요 시 TJ매니저 설정 → ③ P2 연결 시험**을 이용하세요. TJ매니저가 이미 연결 중이면 충돌 가능성이 있습니다.

## 진단과 확인 범위

실패하면 **진단 결과 복사**를 누르고 현재 ChatGPT 대화에 붙여넣어 주세요. 공유 버튼도 사용할 수 있습니다. 개인정보, MAC, 비밀번호, 원본 패킷은 진단에 넣지 않습니다.

| 코드 | 의미 |
| --- | --- |
| W21 / W25 | 주변 검색 또는 무선 연결 실패·시간 초과 |
| W24 | 선택한 반주기와 현재 직접 연결이 다름 |
| A03 | 휴대폰의 현재 직접 Wi-Fi 주소를 읽지 못함 |
| A01 / 3003 | 초기 응답이 성공 형식이 아님. 3003의 정확한 의미는 미확인 |
| A02 | 초기 연결 응답 시간 초과 |
| I01 | 저장된 반주기 식별정보와 불일치 |
| READY | 통신 연결 및 반주기 식별정보 확인 완료 |
| P10 | 시작 요청에 대한 응답. 실제 소리 확인과는 별도 |

사용자 확인은 0.4에서의 10909번 시작·취소입니다. 공유된 진단 일부에서 취소 응답 `4100 / 12`, READY 복귀, 약 1분 동안 연결 확인 신호가 이어진 사실을 확인했습니다. 해당 부분에 시작 요청 자체는 포함되어 있지 않습니다. NFC 없이 새 연결하기, 여러 휴대폰 동시 접속, 장시간 안정성은 별도 실기 확인이 필요합니다. iPhone 직접 제어는 아직 지원하지 않습니다.

## 개발 검증과 저장 방식

`gradle -p p2-direct :core:test :app:testDebugUnitTest :app:assembleDebug :app:lintDebug`

기존 통신·검색·Wi-Fi 연결 테스트에 더해, 암호화 저장·재시작 복원·삭제·손상 검출·잘못된 키·저장 실패 시 기존 정보 보존·반복 신호 후 시작/취소 기록 보존을 검사합니다. 에뮬레이션 검증은 실제 반주기 및 휴대폰 Keystore 검증을 대체하지 않습니다.

프로필은 Android Keystore의 AES-256-GCM 키로 암호화하고 앱 전용 백업 제외 디렉터리에 원자적으로 저장합니다. 공개 저장소에는 공식 앱 APK/복원 코드와 개인 통신 기록을 포함하지 않습니다. 참고: [Android KeyGenParameterSpec](https://developer.android.com/reference/android/security/keystore/KeyGenParameterSpec).

0.5부터 배포 서명키를 별도로 보관해 이후 같은 앱 ID(`kr.neutinamu.p2.direct`)로 업데이트할 수 있도록 구성했습니다. CI의 임시 디버그 APK는 검증용이며, 사용자에게 제공하는 APK는 디버그 기능을 끈 릴리스 빌드를 별도 배포 키로 서명합니다. 개인 키와 연결 정보는 저장소와 CI 산출물에 포함하지 않습니다.
