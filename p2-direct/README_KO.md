# P2 연결진단 시험판 0.2

사용자가 제공한 2026-11-06 PCAP와 **10909번 실행·취소 조작 확인**을 바탕으로 만든 안드로이드 실험용 앱입니다. PC, IR 중계기, 8자리 중계 연결번호를 사용하지 않습니다. 기존 웹앱과 `/wk/`는 변경하지 않았습니다.

**0.1 실제 시험에서 제목 검색은 되었지만 초기 연결이 완료되지 않았습니다.** 사용자 화면에는 초기 응답이 기록과 다르다는 상황이 나타났습니다. 원래 코드는 다른 응답을 모두 “승인하지 않았습니다”라고 단정했습니다. 0.2는 실제 응답값·길이를 표시하여 원인을 수집하는 진단판이며, 인증 문제가 해결되었다고 주장하지 않습니다. GitHub Pages에 올려 쓰는 일반 웹앱의 완성판이나 아이폰 앱이 아닙니다. PCAP에서 발견한 P2 TCP 통신은 일반 Chrome/Safari 웹페이지가 직접 보낼 수 없어 네이티브 Android 앱으로 시험합니다.

## 0.2 수정 사항

- 초기 응답이 다르면 `[A01]`, 응답 길이, 숫자 응답값을 표시합니다. 단순 거절인지 다른 형식인지 아직 단정하지 않습니다.
- 연결 전 시작·취소 버튼을 눌러도 안내창과 버튼 옆 메시지가 나옵니다. 비활성 버튼 때문에 무반응처럼 보이던 부분을 수정했습니다.
- 연결 상태와 실행 결과를 실행 버튼 위에서도 표시합니다.
- 진단 결과 복사·공유 버튼으로 사용자가 직접 기록을 전달할 수 있습니다. 자동 전송하지 않으며, 원본 패킷·전화번호·MAC·기기 식별값·주소는 기록하지 않습니다.
- 초기 연결 시간 초과, 반주기 식별 불일치, 시작 응답만 수신, 실제 재생 확인 미수신을 서로 다른 코드로 구분합니다.
- `P2 연결진단`이라는 별도 아이콘으로 설치됩니다. 기존 0.1 앱을 지울 필요가 없습니다. 기존 시험판의 임시 서명키를 보관하지 않아 동일 패키지 업데이트가 아닌 별도 진단 패키지를 사용합니다.

## 구현 범위

- 기존 저장소 곡 목록을 앱에 포함해 제목·가수·곡번호로 검색합니다. 입력 중 자동 실행하지 않습니다.
- PCAPdroid 파일에서 초기 연결 메시지와 해당 P2 식별값만 메모리로 불러옵니다. 원본 파일·개인정보·비밀번호를 서버로 업로드하지 않습니다.
- 이미 연결된 P2의 로컬 Wi-Fi 경로를 사용해 TCP 7070에 연결합니다.
- 초기 응답 뒤 기기 식별값을 비교하고, 일치하는 경우에만 시작·취소 명령을 전송합니다. 연결 전 버튼을 누르면 연결 안내를 보여 줍니다.
- 사용자가 시작을 누르면 곡번호를 전송하고, 취소를 누르면 확인된 취소 명령을 전송합니다.
- TCP 분할·합쳐진 패킷, 연결 유지 응답, 중복 클릭, 응답 시간 초과, 연결 종료를 처리합니다.
- 시작 요청 응답만으로 재생 성공을 표시하지 않습니다. 일치하는 4300 곡번호 메시지를 받아야 재생 상태 수신으로 표시합니다. 화면·소리 확인은 별도로 필요합니다.
- 명령을 자동으로 재전송하지 않습니다.

## 시험 순서 (같은 안드로이드 휴대폰·같은 P2)

1. 빌드된 `app-debug.apk`를 설치하면 **P2 연결진단** 아이콘이 생깁니다. 시험용 서명이며 정식 스토어 배포판이 아닙니다.
2. TJ매니저에서 평소처럼 NFC로 P2에 연결한 뒤 **홈 버튼으로 나옵니다**. Wi-Fi 연결은 유지해야 합니다. PCAPdroid 캡처는 중지합니다.
3. 시험 앱에서 **내 PCAP 연결 기록 선택**을 누르고 공유했던 `.pcap` 파일을 선택합니다.
4. **P2 연결 시험**을 누릅니다. `P2 연결 응답 확인`이 나오는지 확인합니다.
5. `10909`를 입력하거나 곡을 검색해 선택한 뒤 **선택한 곡 시작**을 누릅니다.
6. 실제 P2에서 노래가 시작되는지 확인하고 **현재 곡 취소**를 눌러 멈추는지 확인합니다.
7. 연결이 완료되지 않으면 `[A01]` 등 표시된 문구를 알려 주세요. 또는 화면 아래 **진단 결과 공유 → ChatGPT**로 내용을 보내 주세요. 연결정보를 바꾸거나 새로운 제어 명령을 추측해서 보내지는 않습니다.

공식 앱이 다른 앱의 연결을 허용하지 않거나 홈으로 나올 때 Wi-Fi 연결이 끊기면 이 시험 방식으로는 진행되지 않을 수 있습니다. 이때 무조건 공식 앱의 연결 해제를 누르면 Wi-Fi도 끊길 수 있습니다.

## 남은 확인 사항

- 초기 연결 메시지의 식별자 필드 및 불명확한 헤더 값의 의미, 새 세션에서의 재사용 가능 여부.
- 동일 연결에서 두 번째 곡·여러 곡 연속 실행. 한 곡의 캡처만으로 헤더가 고정값이라고 단정할 수 없습니다.
- 공식 앱 없이 새 Wi-Fi/NFC 연결을 만드는 과정.
- iPhone 연결 방식 및 네이티브 앱 배포. 안드로이드 시험 결과를 아이폰 동작 보장으로 해석하면 안 됩니다.
- 예약·우선예약·음정·템포 등 기록에서 확인하지 않은 명령은 구현하지 않았습니다.

## 검증과 빌드

Java 17, Gradle 8.11.1, Android SDK 35, AGP 8.9.2:

```sh
gradle -p p2-direct :core:test :core:jar :app:testDebugUnitTest :app:assembleDebug :app:lintDebug
```

PR의 `P2 direct Android trial` workflow가 단위 테스트, APK 빌드, Android lint, 포함된 두 곡 목록 파일을 확인합니다. 프로토콜 테스트는 모의 TCP 서버, 화면 테스트는 Robolectric의 Android 9·15 환경입니다. 물리 P2나 실제 휴대폰 검증과 다릅니다.

로컬 원본 PCAP를 외부 전송하지 않고 가져오기 기능만 확인:

```sh
java -cp p2-direct/core/build/libs/core.jar kr.neutinamu.p2.Inspect /private/path/capture.pcap
```

PCAP 가져오기는 little-endian classic PCAP, raw IPv4/TCP, 로컬 기기 7070 흐름을 지원합니다. PCAPNG, IP 단편, TCP 시퀀스 wraparound, 일부만 겹치는 재전송은 지원하지 않습니다. 누락된 기록이나 서로 다른 여러 기기의 기록은 거부합니다. 원본 PCAP나 인증값을 커밋하지 마세요.

참고: [Chrome Direct Sockets 제한](https://developer.chrome.com/docs/iwa/direct-sockets), [Android Wi-Fi Direct](https://developer.android.com/develop/connectivity/wifi/wifip2p).
